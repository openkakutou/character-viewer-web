# Visual regression fixture pairs a hand-authored `.def` with this repo's own existing WASM testdata

**Context:** Backlog item 019 needs baseline screenshots of three real rendered surfaces (the sprite browser's decoded sprite, the animation player's Clsn overlay on/off, the palette picker's live-recolored preview), driven from a real character fixture through the app's real folder-picker input (this app has no wizard, unlike `character-editor`'s equivalent item — see its own `.vibe/decisions/017`). A CI-running visual suite needs the actual fixture bytes present at test time, not a path to an external corpus.

**Decision:** The suite drives the app through its real `<input webkitdirectory>` folder picker against a vendored fixture folder (`tests/visual/fixtures/character-pack/`) containing a small, hand-authored `.def` (`[Info]` + a `[Files]` section referencing the other three by basename) paired with byte-for-byte copies of this repo's own existing, already WASM-verified fixtures — `src/wasm/testdata/{v1-basic.sff,sample.air,sample.cns}` — rather than a separately-authored sprite sheet or animation set. For the palette-override upload test, it reuses `cyclops-v1-palette1.act`, a real, valid 768-byte external palette already vendored elsewhere in this org (`character`'s and `sff`'s own WASM testdata) for the identical "external `.act` override" purpose, copied into `tests/visual/fixtures/`. Confirmed once, against the real WASM module (not asserted from the same mapping code under test), that applying it to the fixture sprite (57×103, group 0 image 0) visibly recolors 3204 of its 5871 pixels.

**Reason:** `sample.air`/`sample.cns`/`v1-basic.sff` are already real, already WASM-verified fixtures this repo's own `src/wasm/bridge.test.ts` pins expected values against — reusing them here needs only a small text `.def` to glue them into a loadable folder, avoiding a second, independently-authored sprite/animation set purely for this suite. `sample.air`'s Action 200 already carries a `Clsn2Default` box on its first frame (the only frame referencing an image that actually exists in the one-sprite `v1-basic.sff`), which is exactly what the animation player's Clsn-overlay-on/off baselines need with zero extra authoring. This mirrors the sibling `lifebar-viewer-web`'s own identical shape (`.vibe/decisions/010` there): pair a small synthetic `.def` with an already-real, already-accepted binary fixture rather than vendor or hand-author a second one.

**Rejected alternatives:**
- A brand-new, purpose-authored `.sff`/`.air`/`.cns` set for this suite alone — rejected: `src/wasm/testdata/` already has real, WASM-verified fixtures covering exactly what's needed (a decodable sprite, an animation with a real Clsn box); a second set would duplicate that for no benefit, the same reasoning `character-editor`'s own `.vibe/decisions/017` already applied to its wizard-fixture choice.
- Driving the suite through the wizard flow the way `character-editor` does — not applicable here: this app is folder-input-only (no character creation wizard exists), so there is no wizard path to reuse.
- A new, purpose-authored `.act` palette file — rejected: `cyclops-v1-palette1.act` is already a real, valid, already-accepted-into-this-org fixture for this exact purpose (`character`'s and `sff`'s own WASM testdata both vendor it already); a second one would be a new, unreviewed binary asset for no behavioral gain.
