# Module: input
**Role:** Gathers a character's 4 required files (`.def`/`.air`/`.sff`/`.cns`) across any number of file-picker/drag-and-drop gestures, validating them as they arrive (missing kind, same-gesture duplicate kind, unreadable file), then feeds the completed set through the `wasm` bridge to load the character. Also renders the file-picker + drag-and-drop UI that drives this logic — a keyboard/screen-reader-first native file input alongside the drop zone, with per-slot status/errors and a loading/success/error status region. On success, also threads the raw `.sff` bytes it already read back out (`CharacterInputResult.sffBytes`, `onLoaded`'s second argument) — not re-read — so a caller can later decode a specific sprite's pixels on demand (item 005, `.vibe/decisions/006`).
**Files:** `src/input/character-file-input.ts`, `src/input/character-file-input-view.ts`
**Exports:** `mergeFiles(current, incoming): MergeFilesResult`, `missingKinds(slots): RequiredFileKind[]`, `isComplete(slots): slots is CompleteFileSlots`, `readFileAsBytes(file): Promise<Uint8Array>`, `loadCharacterFromSlots(slots, options?): Promise<CharacterInputResult>`, `renderCharacterFileInput(root, options): void`, `RequiredFileKind`, `REQUIRED_FILE_KINDS`, `EXTENSION_BY_KIND`, `FileSlots`, `CompleteFileSlots`, `DuplicateKindError`, `MergeFilesResult`, `FileReadError`, `CharacterInputResult`, `CharacterFileInputOptions`, `CharacterFileInputViewOptions`
**Depends on:** `modules/wasm.md` (`loadCharacter`, `CharacterData`, `WasmBridgeOptions`)
