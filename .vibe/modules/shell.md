# Module: shell
**Role:** The launch screen → persistent workspace transition (backlog item 020). `launch-screen.ts` renders a full-frame wrapper around `input`'s existing file input view — no toolbar/sidebar chrome, since nothing else exists to navigate to before a character loads. Once its `onLoaded` callback fires, `workspace-shell.ts` replaces the launch screen entirely with a persistent `wuik-app-shell`: a toolbar (app title/version + the character's name + a `<wuik-locale-switcher>`, item 018) and a vertical `wuik-tabs` unit (tab-list strip + one `wuik-tab-panel` per section — Characteristics, Palette, Sprites, Animation from `viewer`, In-game preview and Special Moves from `game-mode` (items 008, 009)) composed and laid out as one piece via CSS Grid on the tabs host element, since `wuik-app-shell`'s own sidebar/main slots can't be split across the component (`.vibe/decisions/011`). Every section's render function is called exactly once and stays mounted for the life of the shell — `wuik-tabs` only toggles a panel's `hidden` attribute on switch, never destroying/re-rendering it, which is what lets each section keep its own selection, expanded groups, and playback position across switches with no extra plumbing. A single `MutationObserver` watches every panel's `hidden` attribute and reacts to it flipping: pausing the animation player and, separately, the in-game preview's and the Special Moves list's own trigger playback (each via its own `pause()` handle method) when their panel becomes hidden, and moving focus to the newly visible panel's own heading (`h1`–`h3`) — the only two behaviors `wuik-tabs` itself has no event for. Characteristics is created first and never receives a `hidden` mutation of its own on initial mount (nothing hid it), so its first-mount focus move is done explicitly rather than through the observer. On a locale change (item 018), `workspace-shell.ts`'s own subscription retranslates the toolbar's locale-switcher label, re-invokes `renderCharacteristicsPanel` (which owns no state of its own), and retranslates every section tab: `wuik-tabs` has no supported API to relabel an already-mounted tab, so this both updates each panel's `label` attribute (the source of truth for any future rebuild) *and* reaches directly into `wuik-tabs`'s shadow DOM to rewrite the already-rendered tab buttons' `textContent` by index — never removing/recreating the button, so `aria-selected` and keyboard focus survive untouched (`.vibe/decisions/019-i18n-integration-approach.md`). A toolbar "Load character…" button (item 021) opens a `wuik-dialog` hosting `input`'s `renderCharacterFileInput` again, rendered fresh on every open so a cancelled/failed previous attempt never leaks into the next one; only a successful load (`onLoaded`) closes the dialog and calls the shell's own internal `loadCharacterIntoSections`, which pauses whichever previous playback handles exist, then re-invokes every section's render function on its *already-existing* container — resetting each section's state to default the same way it does on first mount — without ever recreating `wuik-tabs`/its panels, which is what keeps the sidebar's currently active section selected (`wuik-tabs` has no public API to reselect a specific tab, `.vibe/decisions/011`; see `.vibe/decisions/021-mid-session-character-switch-preserves-tabs-instance.md`).
