# Module: export
**Role:** Builds a downloadable animated GIF from an already-loaded character's Animation data (backlog item 014), reusing the same resolved-sprite + palette pipeline `modules/viewer.md`'s animation player already uses for live playback rather than a separate rendering path. Since a GIF's logical screen has one fixed size shared by every frame, frames whose sprites differ in size are first composited onto a shared canvas sized to the union of every referenced sprite's bounding box relative to its own axis (pivot) point — the same axis-offset convention `animation-player.ts`'s own collision-box overlay already established — before being quantized and encoded with the third-party `gifenc` library; see `.vibe/decisions/015-gif-export-frame-compositing.md`. A blank frame (the `.air` "no sprite" sentinel), or one whose sprite this character's own sprite list doesn't contain (malformed/partial data), is written as a single fully transparent color instead of being decoded. `renderGifExportControls` mounts two buttons directly into the animation player's own panel: "Export GIF" (whatever animation and palette override is currently shown there, read via getters at click time so a later selection change can't affect an export already in flight) and "Export Stand" (always Animation 0 — MUGEN/Ikemen's own "standing animation" convention, not resolved via a Statedef lookup; `null` shows a clear inline error instead of downloading anything — see `.vibe/decisions/016-stand-animation-identification-and-export-filenames.md`). Both buttons stay enabled at all times (never pre-emptively disabled for a state that can't currently succeed — same convention as `modules/game-mode.md`'s Special Moves list) but are disabled for the duration of any export in progress, which alone is enough to block a repeat click since a disabled `<button>` fires neither pointer nor keyboard activation under any browser (verified) — no extra in-flight guard flag needed.
**Files:** `src/export/gif-export.ts`, `src/export/gifenc.d.ts` (ambient types for the untyped `gifenc` npm package)
**Exports:** `GifFrameOffset`, `GifCanvasLayout`, `computeGifCanvasLayout(frames, spriteByKey): GifCanvasLayout`, `compositeFrameRgba(pixels, spriteWidth, spriteHeight, canvasWidth, canvasHeight, offsetX, offsetY): Uint8Array`, `resolveStandAnimation(character): Animation | null`, `sanitizeForFilename(value): string`, `buildGifFilename(characterName, label): string`, `GifExportResult`, `EncodeAnimationGifOptions`, `encodeAnimationGif(sffBytes, character, animation, overridePaletteBytes, options?): Promise<GifExportResult>`, `GifExportControlsOptions`, `renderGifExportControls(container, character, sffBytes, getCurrentAnimation, getPaletteOverride, options?): void`
**Depends on:** `modules/viewer.md` (`animation-timing.ts`'s `MS_PER_TICK`/`effectiveTickDuration`/`isBlankFrame` — not `animation-player.ts` itself, which in turn imports *this* module to mount its own export buttons; see `animation-timing.ts`'s own header for why the shared timing helpers live in a separate file to avoid that cycle), `modules/wasm.md` (`resolveSpritePixels`, `CharacterData`, `Animation`, `Frame`, `Sprite`), the third-party `gifenc` npm package (quantize/applyPalette/GIFEncoder)
