# Module: viewer
**Role:** Screens that display an already-loaded character's data, both rendered inline automatically as soon as a character loads — no tab/sidebar navigation yet (see `.vibe/decisions/005-characteristics-panel-inline-no-tab-navigation-yet.md`). The characteristics panel: name, animation count, total sprite count (individual sprites summed across all sprite groups), and the sorted list of Statedef numbers (duplicates shown as-is, not deduplicated). The sprite browser (item 005): a collapsed-by-default list of sprite groups — expanding one lazily mounts only its own sprite rows, so a sheet with hundreds of sprites never dumps hundreds of DOM nodes at once — and a preview `<canvas>` that decodes and shows the selected sprite's actual pixels on demand (`wasm.resolveSpritePixels`), scaled to fit a fixed-size stage via `computeScaleToFit` (downscales an oversized sprite, upscales a tiny one up to an 8x cap) rather than left at native size. A monotonically increasing selection token discards a slower, superseded decode instead of letting it overwrite a newer selection's preview. Uses a plain `<canvas>`, not `web-ui-kit`'s `<wuik-viewport>` — that control isn't actually installable via npm yet (`.vibe/decisions/007`).
**Files:** `src/viewer/characteristics-panel.ts`, `src/viewer/sprite-browser.ts`
**Exports:** `renderCharacteristicsPanel(root: HTMLElement, character: CharacterData | null): void`, `renderSpriteBrowser(root: HTMLElement, character: CharacterData | null, sffBytes: Uint8Array | null, options?: SpriteBrowserOptions): void`, `computeScaleToFit(width: number, height: number): number`, `SpriteBrowserOptions`
**Depends on:** `modules/wasm.md` (`CharacterData`, `resolveSpritePixels`, `SpritePixelResult`, `WasmBridgeOptions`)
