# Module: viewer
**Role:** Screens that display an already-loaded character's data, all rendered inline automatically as soon as a character loads — no tab/sidebar navigation yet (see `.vibe/decisions/005-characteristics-panel-inline-no-tab-navigation-yet.md`). The characteristics panel: name, animation count, total sprite count (individual sprites summed across all sprite groups), and the sorted list of Statedef numbers (duplicates shown as-is, not deduplicated). The sprite browser (item 005): a collapsed-by-default list of sprite groups — expanding one lazily mounts only its own sprite rows, so a sheet with hundreds of sprites never dumps hundreds of DOM nodes at once — and a preview `<canvas>` that decodes and shows the selected sprite's actual pixels on demand (`wasm.resolveSpritePixels`), scaled to fit a fixed-size stage via `computeScaleToFit` (downscales an oversized sprite, upscales a tiny one up to an 8x cap) rather than left at native size. A monotonically increasing selection token discards a slower, superseded decode instead of letting it overwrite a newer selection's preview. Uses a plain `<canvas>`, not `web-ui-kit`'s `<wuik-viewport>` — that control isn't actually installable via npm yet (`.vibe/decisions/007`). The animation player (item 007): plays an animation's frames back on a `setTimeout` chain paced by each frame's own `time` (game ticks, 1 tick = `MS_PER_TICK`), with play/pause, frame-by-frame stepping (disabled while playing), and a loop toggle that wraps to the animation's `loopStart` instead of stopping at the end — same selection-token-guarded on-demand decode per frame as the sprite browser, reusing its `computeScaleToFit`/`defaultDrawPixels`. A blank frame (the `.air` "no sprite" sentinel — any negative group/image value) shows as empty, no decode attempted. An optional overlay draws each frame's `Clsn1`/`Clsn2` collision boxes on the same native-resolution canvas as the sprite, offset by the sprite's axis point — see `.vibe/decisions/009-animation-player-timing-looping-and-collision-overlay-design.md` for the timing/looping/overlay-color decisions this item had to make that nothing upstream specifies.
