# Module: viewer
**Role:** Screens that display an already-loaded character's data, each rendered once and hosted as one section of `modules/shell.md`'s workspace (item 020 — tab/sidebar navigation, deferred since `.vibe/decisions/005`/`008` until a real workspace shell existed to host it). The characteristics panel: name, animation count, total sprite count (individual sprites summed across all sprite groups), and the sorted list of Statedef numbers (duplicates shown as-is, not deduplicated). Item 012 adds an author line (shown only when the `.def` sets a non-blank one) and a "Files" section listing the referenced sprite/animation/sound/command/constants/state files as labeled, basename-only entries (never the full path; a field with nothing to show is simply omitted, and the whole section is omitted when no field has a value) — `palettes` is deliberately not repeated here since the palette picker already displays it; see `.vibe/decisions/014-characteristics-panel-full-metadata-scope.md`. The sprite browser (item 005): a collapsed-by-default list of sprite groups — expanding one lazily mounts only its own sprite rows, so a sheet with hundreds of sprites never dumps hundreds of DOM nodes at once — and a preview `<canvas>` that decodes and shows the selected sprite's actual pixels on demand (`wasm.resolveSpritePixels`), wrapped in `web-ui-kit`'s `<wuik-viewport>` for zoom/pan/reset-to-fit (item 016, `.vibe/decisions/018` — superseding the local `computeScaleToFit` scale-to-fit this preview used while that control wasn't yet installable, `.vibe/decisions/007`): `resetToFit()` is called, via a duck-typed helper that's a no-op if the method isn't present, every time a newly decoded sprite is drawn, so no selection's preview inherits a previous one's zoom/pan. A monotonically increasing selection token discards a slower, superseded decode instead of letting it overwrite a newer selection's preview — and the same token guard also prevents a stale decode from calling `resetToFit()` on a no-longer-current selection. The animation player (item 007): plays an animation's frames back on a `setTimeout` chain paced by each frame's own `time` (game ticks, 1 tick = `MS_PER_TICK`), with play/pause, frame-by-frame stepping (disabled while playing), and a loop toggle that wraps to the animation's `loopStart` instead of stopping at the end — same selection-token-guarded on-demand decode per frame as the sprite browser, reusing its `computeScaleToFit`/`defaultDrawPixels` for its own still-`<canvas>`-only preview (out of item 016's scope). A blank frame (the `.air` "no sprite" sentinel — any negative group/image value) shows as empty, no decode attempted. An optional overlay draws each frame's `Clsn1`/`Clsn2` collision boxes on the same native-resolution canvas as the sprite, offset by the sprite's axis point — see `.vibe/decisions/009-animation-player-timing-looping-and-collision-overlay-design.md` for the timing/looping/overlay-color decisions this item had to make that nothing upstream specifies. The palette picker (item 006): shows which `.act` files the character's `.def` references (informational only, this app never has their bytes) and lets the user upload one external override, probe-validated against a real sprite via `resolveSpritePixels` before being accepted — see `.vibe/decisions/010`. Both the sprite browser and animation player return a small handle (`setPaletteOverride`) instead of `void`, so the palette picker can push a new override to whichever one is currently shown without a full re-render (losing the current selection/expanded groups/playback state). The animation player's handle also has `pause()` (item 020): stops playback at the current frame, a no-op if already paused — used by `modules/shell.md`'s workspace shell to auto-pause the section when the user navigates away from it while playing, rather than a self-rescheduling `setTimeout` chain continuing to decode frames off-screen. Item 014 mounts `modules/export.md`'s `renderGifExportControls` ("Export GIF"/"Export Stand") into the animation player's own panel, reading its `currentAnimation`/`activeOverride` closures through getters — `MS_PER_TICK`/`effectiveTickDuration`/`isBlankFrame` now live in `animation-timing.ts`, a small dependency-free module, and are re-exported from `animation-player.ts` unchanged for every pre-existing import site; the split exists so `export` (which needs those helpers, and is in turn imported *by* `animation-player.ts` for its own UI) doesn't form an import cycle with `animation-player.ts` itself.
**Files:** `src/viewer/characteristics-panel.ts`, `src/viewer/sprite-browser.ts`, `src/viewer/animation-player.ts`, `src/viewer/animation-timing.ts`, `src/viewer/palette-picker.ts`
**Exports:** `renderCharacteristicsPanel(root: HTMLElement, character: CharacterData | null): void`, `renderSpriteBrowser(root: HTMLElement, character: CharacterData | null, sffBytes: Uint8Array | null, options?: SpriteBrowserOptions): SpriteBrowserHandle`, `SpriteBrowserHandle`, `computeScaleToFit(width: number, height: number): number`, `defaultDrawPixels(canvas, pixels, width, height): void`, `SpriteBrowserOptions`, `renderAnimationPlayer(root: HTMLElement, character: CharacterData | null, sffBytes: Uint8Array | null, options?: AnimationPlayerOptions): AnimationPlayerHandle`, `AnimationPlayerHandle` (`setPaletteOverride`, `pause`), `AnimationPlayerOptions` (now also `encodeAnimationGif`/`triggerDownload`, forwarded to `renderGifExportControls`), `MS_PER_TICK: number`, `effectiveTickDuration(frame: Frame): number`, `isBlankFrame(frame: Frame): boolean`, `clampLoopStart(loopStart: number, framesLength: number): number`, `computeNextFrameIndex(currentIndex: number, framesLength: number, loopStart: number, looping: boolean): number | null`, `computeClsnRect(box: ClsnBox, axisX: number, axisY: number): ClsnRect`, `ClsnRect`, `renderPalettePicker(root: HTMLElement, character: CharacterData | null, sffBytes: Uint8Array | null, options: PalettePickerOptions): void`, `PalettePickerOptions`
**Depends on:** `modules/wasm.md` (`CharacterData`, `resolveSpritePixels`, `SpritePixelResult`, `WasmBridgeOptions`, `Frame`, `ClsnBox`, `Animation`, `Sprite`), `modules/input.md` (`readFileAsBytes`, reused by the palette picker for reading an uploaded `.act` file), `modules/export.md` (`renderGifExportControls`, `GifExportControlsOptions`, mounted by `animation-player.ts`), `modules/i18n.md` (`onLocaleChange`, `t`)

**Localization (item 018):** every screen's static labels/headings/empty-states move through `t()`; a screen with no state of its own (the characteristics panel) is simply re-invoked from `modules/shell.md`'s own locale-change subscription, while every screen owning live/async state (sprite browser, palette picker, animation player) tracks a small "is the preview status currently showing one of this module's own translatable texts (loading/blank), or a raw WASM/bridge error, or already resolved" kind alongside its own subscription to `onLocaleChange`, so only the module's own copy retranslates in place — a raw decode/probe error from the WASM bridge is left untouched, and playback position/selection/expanded groups/active override are never disturbed. The palette picker's pluralized "N palette file(s)" sentence picks an already-translated singular/plural noun and interpolates it into a translated template (never i18next's automatic plural-key suffixing), matching the org-wide convention every sibling app already established.
